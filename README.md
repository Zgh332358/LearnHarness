# Agent Harness 全面拆解指南

给非技术背景读者的 Harness 图文教材。从**输入、输出、执行**出发，沿着同一项任务理解 Agent 怎样持续工作，以及 Harness 在系统架构和当前技术中的位置。

这份指南重点回答三个问题：**模型提出请求以后，谁把它变成真实执行？执行结果怎样进入下一轮输入？整个任务由谁判断继续、暂停和结束？**

## Harness 负责什么

Harness 是围绕模型组织和推进任务的运行程序。它准备本轮输入，接收模型输出，按规则处理工具请求，保存实际执行结果，并组织后续调用。任务需要暂停、恢复或结束时，它还要落实相应的运行规则。

| 对象 | 在任务中负责什么 |
| --- | --- |
| 模型 | 根据本轮输入，产生内容或工具请求 |
| Harness | 组织输入、处理输出、检查请求与授权、安排执行、保存状态、控制继续与结束 |
| 工具与业务系统 | 执行具体操作，返回真实结果，例如查询空位、读取文件或运行测试 |
| Agent 产品 | 将上述能力组成用户可以使用的完整体验，并承担相应的产品与业务规则 |

执行结果被保存后，需要由程序放进后续输入，才能参与模型下一次判断。外部记录、本轮上下文和模型权重各有不同作用。指南逐步拆开这些边界，再解释 Harness 的逻辑职责、部署地点，以及 API、SDK、框架和托管服务的分工。

## 学习路线与内容

第一次建议顺序读第 1—3 章，先走完一项任务，再拆开内部机制。HTML 阅读版每章都有一个具体问题、学习目标和继续阅读入口。

| 阅读阶段 | 章节 | 读完要理解什么 |
| --- | --- | --- |
| 建立完整主线 | 第 1—3 章 | 模型、Harness、工具怎样分工；输入、输出、执行怎样接起来；运行记录怎样支持交付 |
| 拆解运行机制 | 第 4—6 章 | 请求路由、参数与授权检查、失败重试、沙箱与 Hook、继续、暂停和结束 |
| 理解上下文与长任务 | 第 7—10 章 | 本轮输入、容量与压缩；状态、记忆和权重；中断恢复；计划、并行与多 Agent |
| 理解连接与定位 | 第 11—13 章 | MCP、Skill、框架与 SDK；Harness 的架构位置、部署位置和当前产品分工 |
| 判断工作是否办好 | 第 14—15 章 | 验证、评测、日志、质量、费用与延迟；怎样阅读真实项目并迁移到代码任务 |
| 随时回查 | 附录 A—C | 术语对照、十个情境自测及答案、一手资料索引与证据范围 |

有明确问题时，可以按下面的路线进入，再回到前后章节补齐背景：

- **想知道 Harness 在哪里**：第 12 章 → 第 13 章，分别看系统职责与部署、当前产品与技术发展。
- **想知道请求为何还没执行**：第 2 章 → 第 4 章 → 第 5 章，看输出、检查、执行与失败边界。
- **想知道为什么 Agent 会忘记或中断**：第 7 章 → 第 8 章 → 第 9 章，看输入组织、保存状态和恢复规则。
- **想判断 Agent 是否真正完成任务**：第 3 章 → 第 14 章，看实际交付与验证、评测。

## 图解与教学实验

9 幅二维机制图帮助辨别参与者、信息流和职责；4 个预设实验让读者通过推进事件、选择记录或比较预设条件，观察规则怎样影响后续动作。

| 所在章 | 实验 | 理解的关键问题 |
| --- | --- | --- |
| 第 2 章 | 六事件单步与回看 | 请求什么时候变成执行，真实结果什么时候取得，怎样进入下一轮输入 |
| 第 4 章 | 只改一个字段的三层检查 | 格式合法、业务合理与已有授权为什么需要分别检查 |
| 第 7 章 | 勾选记录并组装输入预览 | 为什么外部保存的资料不会自动进入本轮上下文 |
| 第 9 章 | 四个情境与解释反馈 | 什么时候有限重试、核对未知副作用、等待批准或检查业务交付 |

实验为教学模拟，不调用真实模型或餐厅。回看与重新演示只是改变教学视图，不代表撤销外部操作。餐厅、价格、查询返回与运行编号均为自拟教学数据。
