# 量化验收矩阵与旧版诊断

这是供本轮 HTML 改造使用的验收计划，**不是完成结果**。表中“通过条件”需由主任务的实际 HTML 验收填入证据，未运行项记“未测”，不能以源码存在替代结果。标准条款、文档建议、项目目标的区分见 [sources.md](sources.md) 和 [records.json](records.json)。

## 旧版已确认的前端问题

1. 文档没有跳过导航的入口。页首目录 18 个链接，对顺序键盘导航增加负担；这项单页增强不据此单独宣称违反 2.4.1。
2. 切章脚本只滚动目标，没有显式焦点策略。手机点目录后关闭 `details`，可能把当前焦点留在隐藏链接；应在明确切章时移到可见标题。
3. 自定焦点 CSS 未覆盖 `input/select`。它们可能仍有浏览器默认焦点，但缺统一主题控制，需要实际按键检查。
4. 26 张表仅 3 个 `caption`，93 个 `th` 仅 12 个 `scope`。表格内容不必丢弃，补齐可辨主题及行列语义即可。
5. 旧颜色公式核查：muted `#667367` / tint `#e2eddf` ≈ 4.133；muted / soft `#eef2e9` ≈ 4.394；这两组普通文字低于 4.5。焦点 `#6a976b` / tint ≈ 2.785，低于必要非文字目标 3。
6. 宽图/注释字号最低约 10.7px；这不由 WCAG 给出一般最小字号，但对非技术读者长时间看流程存在体验负担。新主题宜给关键图中文字至少 13–14px 的项目目标，并允许放大。
7. 当前 print/noJS 已有退化代码，无需重造；新样式仍要实际复验，不能继承旧静态检查当作新版实测。

## 主任务可优先执行的样本集合

- 视口：320×900、390×844、768×1024、1280×900；至少覆盖首页、第二章、第四章、第七章、第九章、第十章和术语/来源表。尺寸必须记录浏览器实际 CSS viewport，不仅记录请求值。
- 放大：桌面 200% 真实浏览器放大；如环境限制不能设置，记录限制，不把 CSS zoom 或仅缩小 viewport 冒称该测试。
- 核心键盘链：跳过导航 → 目录选章 → 章节标题 → 实验 → 下一章 → 阅读设置 → 返回；另测试四个实验的选项、提交、重置。
- 浅/深主题（如提供）：正文、辅助文字、引用、卡片、状态反馈、输入、焦点各配对计算一次，叠加透明色先算合成实际背景。
- 文字间距覆盖：行距 1.5、段后距 2em、字距 .12em、词距 .16em，核查密图、按钮和英文混排。
- 退化：实际禁用脚本重载和实际 print 介质；保留全文、静态实验、正文链接，不能出现空白教程。
- 性能：记录文件大小/无外部运行资源，保存实际采集值及缺失原因，不宣称线上真实用户通过。

## 审美与验收怎样一起取舍

本教材篇幅长、受众非技术，漂亮应首先表现为稳定阅读节奏、可以辨认的层次、清楚的当前位置与足够亮暗对比。浅灰小字、连续动效、过多浮层、玻璃背景和仅图标工具栏会增加解释成本。验收标准不决定审美风格，但会淘汰读不清、缩放失效、焦点丢失的实现。选择主题时应把这些可执行条件作为先决条件，再比较排版、配色和主题适配。
