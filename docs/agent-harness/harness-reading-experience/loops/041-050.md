# 第 041–050 轮前端诊断

每轮有一个可区分的问题，使用冻结版作为诊断对象；实现阶段集中落实，不伪称改了100版网页。

## A041 · 先从同一实例开始，不让导航成为选择题

来源：[原页](https://diataxis.fr/tutorials/)。观察：作者强调教程围绕具体、可完成的学习经历，避免过早引入大量选择与支线。

当前问题：本教材混合解释和实验，已有同一餐厅任务；导航美化时若加大量卡片入口，会把主线拆散。

本轮决定（调整采用）：首屏仅突出“从第 1 章开始”和“打开目录”，把其他路线放次级区域；保留同一任务的章节顺序，不把四个实验替代为首页四个同等权重的产品卡片。

完成条件：新访客无需选择技术角色即可开始主线；首屏不超过两个主操作；目录仍可回查全部章节。

[完整方法卡](../methods/A041.md)。

## A042 · 每章开头保留可核查的学习问题

来源：[原页](https://react.dev/learn)。观察：React Learn 在正文前列出本页将覆盖的学习点，再进入示例。

当前问题：当前每章已有本章问题与“读完应能”，比单独章题更有助于理解，应作为新版层次中心保留。

本轮决定（采纳）：章首结构固定为章号/题目、一个核心问题、一句可观察目标，然后正文；用字重和间距区分，不再叠放同义摘要或装饰性副标题。

完成条件：15 个正文章都有问题与目标；目标能指向判断、追踪或比较动作；手机首屏能读到核心问题而非被导航卡片占满。

[完整方法卡](../methods/A042.md)。

## A043 · 解释性的交叉阅读有边界

来源：[原页](https://diataxis.fr/explanation/)。观察：解释应围绕明确问题建立连接、提供背景，同时守住主题边界。

当前问题：当前部分段落用“后面章节会展开”提示，但读者需要记住章号再去目录查找。

本轮决定（调整采用）：仅在依赖关系明确处添加短交叉链接，例如“上下文怎么组织 → 第 7 章”；每个链接说明继续理解的具体问题。相关阅读不泛化成每章末推荐十篇。

完成条件：抽查输入/执行/状态/定位四类交叉链接，目标章节正确且主题有关；每一处相关阅读不超过两项。

[完整方法卡](../methods/A043.md)。

## A044 · 核心解释默认可见

来源：[原页](https://design-system.service.gov.uk/components/accordion/)。观察：官方不建议把所有用户必须看到的内容放入折叠组件，优先考虑清晰标题或锚点。

当前问题：当前主解释全部可见，而答案与静态实验对照折叠；重设计若把每小节变成手风琴，会破坏连续阅读。

本轮决定（采纳）：章内定义、因果解释、机制图和关键限制默认可见；仅答案、额外记录或补充示例可折叠。不把核心全文变成层层点击才能读的卡片。

完成条件：关闭所有折叠后仍能完整理解本章核心结论；模型请求与真实执行分界、未知副作用等关键限制不在隐藏区。

[完整方法卡](../methods/A044.md)。

## A045 · 补充展开标签先说明会看到什么

来源：[原页](https://design-system.service.gov.uk/components/details/)。观察：details 适合少数用户才需要的补充信息，summary 应简短描述内容。

当前问题：实验中的静态记录和自测答案已有 details；若 summary 只写“展开”则无法预判内容。

本轮决定（调整采用）：使用“查看六个事件的完整记录”“查看判断依据”等内容型标签；打开后用“收起完整记录”或原标签表达状态，保持原生键盘操作。

完成条件：所有补充 summary 能独立说明内容；Enter/Space 可展开和收起；必需正文不被挪入 details。

[完整方法卡](../methods/A045.md)。

## A046 · 拒绝目录与内容中的嵌套折叠

来源：[原页](https://design-system.service.gov.uk/components/accordion/)。观察：官方建议避免手风琴嵌套；折叠、标签、details 彼此嵌套会增加查找困难。

当前问题：目录已有一层 details，正文已有答案和实验记录；再将每个目录组和每章都做折叠，会形成连续寻找。

本轮决定（舍弃）：桌面目录组只用标题，不嵌套 details；窄屏只由一个“章节目录”入口控制整体。内容保留单层补充展开，实验内不再做二级手风琴。

完成条件：任一章节从打开目录到选择章节最多一次展开；DOM 中没有 details 内的 details；核心内容不会被多层折叠隐藏。

[完整方法卡](../methods/A046.md)。

## A047 · 轻量本地搜索补上回查能力

来源：[原页](https://vitepress.dev/reference/default-theme-search)。观察：VitePress 支持浏览器内索引的本地全文搜索，不必依赖在线服务。

当前问题：当前 3.3 万字中没有 input[type=search]，只能记住章节或依赖浏览器查找；章隐藏会影响常规回查。

本轮决定（调整采用）：在目录上方提供单个本地搜索输入，优先搜索章题和 h3 小节；结果显示所属章及标题，后续才扩展正文短片段。索引在页面本地，不加入 AI 问答或外部 API。

完成条件：离线打开文件，搜索“幂等”“上下文”“MCP”均有正确目标；清空恢复正常目录；没有结果时明确显示无结果并保留输入。

[完整方法卡](../methods/A047.md)。

## A048 · 搜索结果以标题优先，保持可辨认上下文

来源：[原页](https://vitepress.dev/reference/default-theme-search)。观察：本地搜索配置示例对标题赋予更高权重，也提供结果详情与无结果的本地化文字。

当前问题：新增搜索若只给任意命中段落，非技术读者会收到许多没有章节背景的碎片。

本轮决定（调整采用）：结果先按章题/小节题命中排序，显示“章号 · 章名 / 小节名”；若搜正文，每项只带一个短上下文片段，限制首屏结果数，不生成脱离原文的答案。

完成条件：同一关键词命中标题和正文时，标题结果优先；点击结果到具体小节；一条结果不重复章题三次，不把实验反馈的多段长文塞满列表。

[完整方法卡](../methods/A048.md)。

## A049 · 导航固定层不能遮挡正文与焦点

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。观察：官方解释指出固定头尾与持续展开的导航可能遮住键盘焦点，可用滚动留白等方式避免。

当前问题：现有 scroll-padding-top=28px 和 back-top 固定按钮适合旧布局；若新增顶部导航，其真实高度可能超过 28px。

本轮决定（采纳）：定位留白由新版固定栏高度控制，h2/h3/实验锚点均使用一致 scroll-margin；手机目录打开后不覆盖可继续聚焦的正文。返回顶部按钮避开实验操作区。

完成条件：在 390px、1280px 和 200% 缩放下逐一跳章/小节、Tab 到实验按钮，焦点组件始终至少部分可见；实际目标标题完整可见作为本项目更高要求。

[完整方法卡](../methods/A049.md)。

## A050 · 跳过导航直接进入正文

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/bypass-blocks.html)。观察：官方说明让顺序键盘用户跳过重复导航，可更快抵达主内容；单页也可采用这一有益设计。

当前问题：当前 body 先是封面与 18 个目录链接，没有跳过导航链接；键盘读者需经过多项导航再到正文。

本轮决定（采纳）：body 首个交互项加入“跳到正文”；聚焦时显现，激活后把焦点送到当前章节标题或 main。保留 main 和明确的导航 landmark，不用零尺寸隐身链接。

完成条件：首次 Tab 即显示跳到正文；Enter 后焦点位于可见正文，下一次 Tab 进入正文链接/实验而非重新遍历目录；不把单页采用此法等同宣布 WCAG 全面合规。

[完整方法卡](../methods/A050.md)。
