# 第 081–090 轮前端诊断

每轮有一个可区分的问题，使用冻结版作为诊断对象；实现阶段集中落实，不伪称改了100版网页。

## A081 · Tab 聚焦时避开手机底部阅读栏

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。观察：作者添加的内容不能让获得键盘焦点的组件完全被遮住；固定通知、顶栏尤其需要检查。

当前问题：新版拟增加手机底部位置栏。标题定位留白解决顶部跳转，不能替代逐项Tab到页面尾部控件的底栏遮挡检查。

本轮决定（调整采用）：为主文尾部与视口底部设置阅读留白和 scroll-padding-bottom；实际以Tab/程序焦点模拟核查实验末尾按钮，不能只看标题锚点。

完成条件：390及320 CSS px宽，实验末尾控件聚焦后完整位于顶栏和底栏之间；缩放后重复。

[完整方法卡](../methods/A081.md)。

## A082 · 阅读设置优先行内展开，减少模态负担

来源：[原页](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。观察：真正模态对话框需要焦点进入内部、Tab 留在内部、Escape 关闭、关闭后回到触发处，并使背景不可操作。

当前问题：旧版没有 dialog，字号/目录等轻操作无须增加遮住全文的弹窗。

本轮决定（舍弃）：拒绝把普通阅读设置设计成自制模态；优先原生 details 行内展开。若后来采用真模态，按完整对话框约定验收。

完成条件：阅读设置和目录可在当前上下文中打开关闭，不因视觉弹层丢失焦点；如存在模态，额外测试 Escape、回焦点和背景不可操作。

[完整方法卡](../methods/A082.md)。

## A083 · 可读名称、角色、状态与视觉一致

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html)。观察：控件的名称和角色可被程序确定，用户可改的状态和值应可被确定和通知；标准控件按规范使用可减少额外工作。

当前问题：旧版使用 label、fieldset 和 ARIA，但新增图标按钮或阅读设置可能只有视觉符号。

本轮决定（采纳）：所有设置写明可见名称；自定义展开控件同步 aria-expanded；当前章节同步 aria-current；图标不能独自承担名称。

完成条件：每个 button/input/select 有可确定的名称；全部 aria-labelledby/controls 指向存在且唯一的 ID；展开和章节状态与 DOM 可见性一致。

[完整方法卡](../methods/A083.md)。

## A084 · 反馈被告知，正文变化不大段抢读

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。观察：不移动焦点的状态信息应通过角色或属性让辅助技术获知；不应把所有动态内容都做成不断播报的区域。

当前问题：旧版实验反馈已有 polite/live 状态区，可保留；新增搜索结果数量和恢复提示需要同类处理。

本轮决定（调整采用）：只让简短反馈/结果计数使用 role=status 或 polite live；大段文章和整个目录不设置 live。

完成条件：每次选择/提交得到明确文字反馈；需要播报的反馈区有状态语义；切章不将全章放进 aria-live。真实读屏结果需单独标明测试范围。

[完整方法卡](../methods/A084.md)。

## A085 · 正文、辅助文案与链接都达到文字对比目标

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。观察：普通文本最低 4.5:1，大字号文本可用 3:1；计算值不能四舍五入到刚好及格。

当前问题：旧 muted #667367 在 tint #e2eddf 上约 4.133，在 soft #eef2e9 上约 4.394，低于普通文字 4.5；主纸色上约 4.731。

本轮决定（调整采用）：加深辅助文案色；为每个主题检查正文、注释、链接和卡片背景的配对，避免“精致浅灰”压低可读性。

完成条件：保存主题颜色配对计算表；所有正常使用的普通文字配对原始比值至少 4.5，不通过圆整凑阈值；例外需写明范围。

[完整方法卡](../methods/A085.md)。

## A086 · 必要边界和焦点指示有足够非文字对比

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。观察：识别控件及状态所必需的视觉信息、理解图形所必需的部分，要与相邻颜色达到 3:1；纯装饰不在同一范围。

当前问题：旧自定焦点 #6a976b 在 tint #e2eddf 上约 2.785；细浅边框 #d5ded2/白约 1.369，不能独自承担输入识别。

本轮决定（调整采用）：加深焦点环和必要输入边界；保留浅装饰分隔线，但给操作区使用明确文字、形状和必要的高对比边界。

完成条件：逐一记录自定焦点环、输入边界、必读箭头/状态标记与相邻背景的配对；必需项至少 3:1，装饰项不混作标准失败。

[完整方法卡](../methods/A086.md)。

## A087 · 成功、失败、当前状态不只靠颜色

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。观察：颜色不能是表达信息、动作、提示或区分元素的唯一视觉手段。

当前问题：旧版当前目录有边线和加重，实验有反馈文字；新的强调色不能把“允许/拒绝”简化为红绿底色。

本轮决定（采纳）：状态保留文字标签；当前目录同时用位置标志与字重；错误使用文字原因，箭头标注数据/动作。

完成条件：关闭颜色或查看灰度截图后，仍能辨认当前章、已选操作、允许/拒绝与正确反馈，不需要猜测色义。

[完整方法卡](../methods/A087.md)。

## A088 · 文字放大两倍仍能读和操作

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。观察：文本应可放大至 200% 而不丢失内容和功能；控件标签也属于需考虑的文本。

当前问题：旧版字体多用 px，未禁止浏览器缩放，但放大后的控件、图注和目录没有本轮实测证据。

本轮决定（调整采用）：改为相对字号和可伸缩容器；保留浏览器缩放；阅读字号设置可以辅助，不能代替浏览器放大验收。

完成条件：100%、125%、150%、200% 浏览器放大中，正文、图注、操作标签没有截断/重叠，所有阅读与实验功能可达。

[完整方法卡](../methods/A088.md)。

## A089 · 320 CSS px 时正文只需竖向阅读

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。观察：竖向内容应在等效 320 CSS px 宽度重排，避免双向滚动；真正二维数据表等可局部滚动。

当前问题：旧版已有单栏断点和局部宽表容器，但整体 320px、图节点和较长工具栏需重新核查。

本轮决定（调整采用）：正文和实验在窄屏堆叠；复杂表格只在有名称的局部容器横滚；长英文/ID 可折行。

完成条件：320px 下 document.scrollWidth 不超过 clientWidth；正文无横滚；允许横滚的表格局部边界不溢出页面且键盘可达。另在桌面 400% 放大核查。

[完整方法卡](../methods/A089.md)。

## A090 · 用户调整文字间距不损坏布局

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)。观察：用户覆盖行距 1.5、段后距 2、字距 .12、词距 .16 倍字号时，不应丢信息或功能；语言特性有适用范围。

当前问题：旧版正文行距已为 1.9，但这不等于用户覆盖间距后的控件与图形已经通过。

本轮决定（调整采用）：避免固定文本高度和省略必需文案；中文主要核查行/段/字间距，混排英文同时观察词距。

完成条件：注入指定间距覆盖样式，在首页、图最密章和四个实验核查：不出现文本裁切、重叠或按钮失去名称；不能仅以原始 line-height 宣称通过。

[完整方法卡](../methods/A090.md)。
