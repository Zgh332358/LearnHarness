# 第 071–080 轮前端诊断

每轮有一个可区分的问题，使用冻结版作为诊断对象；实现阶段集中落实，不伪称改了100版网页。

## A071 · 窄屏表格按数据性质选择保留关系

来源：[原页](https://designsystem.digital.gov/components/table/)。观察：USWDS 建议窄屏数值横向比较可滚动，目录式信息可堆叠，并尽量减少列。

当前问题：目前所有 reading-table 统一 min-width 540/570px 横向滚动；术语目录与角色比较都套同一处理。

本轮决定（调整采用）：角色/阶段跨列关系保留滚动表格并给可见提示；术语、来源等目录可改成字段明确的堆叠行。只让表格滚动，不让整页溢出。

完成条件：窄屏能发现表格横向可读；滚动时角色列/表头语义仍可查；来源链接和术语不会被要求不断左右拖动；整页宽度等于视口。

[完整方法卡](../methods/A071.md)。

## A072 · 代码与工作单有不同阅读提示

来源：[原页](https://www.carbondesignsystem.com/building-blocks/core/components/code-snippet/guidelines)。观察：Carbon 将行内、单行、多行片段区分，片段是只读内容。

当前问题：输入工作单、JSON 请求和伪代码都用 pre/code 软色块；非技术读者可能把全部内容当成必须运行的程序。

本轮决定（调整采用）：为长块写清“输入工作单”“请求结构示例”“示意代码”；行内术语只轻度标记，JSON 采用舒适行距和低饱和语法色，保留可选择文本。

完成条件：每个长块不用读语法就知道用途；教学工作单不配运行按钮；关键字段清晰可读；手机长字符串可在自身区域处理。

[完整方法卡](../methods/A072.md)。

## A073 · 复制只服务于真正可复用的内容

来源：[原页](https://www.carbondesignsystem.com/building-blocks/core/components/code-snippet/guidelines)。观察：Carbon 复制功能为可选，需成功确认；内容必须保持可复制的正确形式。

当前问题：现有示例多为概念教学数据，没有复制按钮；默认增加全页复制会增加操作噪声。

本轮决定（舍弃）：本轮不统一添加每段复制按钮。仅在后续出现可复用检查清单或模板时增设明确“复制模板”；成功提示以实际复制结果为准，失败保留手选文本。

完成条件：正文不因复制按钮增密；不存在示例可直接执行的暗示；若实现复制，内容与看到的文本一致，失败不显示已复制。

[完整方法卡](../methods/A073.md)。

## A074 · 图解使用有限且一致的视觉编码

来源：[原页](https://designsystem.digital.gov/components/data-visualizations/)。观察：USWDS 建议围绕一个中心意思、克制颜色，并提供文字说明和非颜色区分。

当前问题：多数 diag-node 都以 currentColor 实线框显示，边界虚线含义未统一；小字号的箭头标签较难扫读。

本轮决定（调整采用）：规定角色、数据、边界的少量视觉语法：角色有名称，流向有动词，范围以明确虚线/标题表示；颜色只辅助输入、执行、结果区分。每图保留问题与可读结论。

完成条件：去掉颜色也可追踪流向；同种边框不跨图变义；箭头标签窄屏至少正常可读；图不靠悬停才能获取关键因果。

[完整方法卡](../methods/A074.md)。

## A075 · 交互先让读者看见输入与输出

来源：[原页](https://www.redblobgames.com/pathfinding/a-star/introduction.html)。观察：Red Blob 先解释输入图与输出路径，再将算法分解为可逐步观察的过程。

当前问题：六事件实验已有负责者、阶段输入、阶段输出；新布局若只强调动画或角色图，会丢失可核对的数据。

本轮决定（采纳）：将输入、输出、执行责任保持为每次观察的固定槽位，重复用同一餐厅案例。每次变化围绕当前一个问题，不加入自由拖拽或无明确意义的参数。

完成条件：每步能回答谁收到什么、谁产生什么；Q01/Q02 与返回记录保持配对；模型提出请求不会提前染成真实执行完成；无交互时仍有静态对照。

[完整方法卡](../methods/A075.md)。

## A076 · 用明确 landmark 名称区分三种阅读区域

来源：[原页](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA11)。观察：W3C Bypass Blocks 说明结构标记有助于绕过和定位页面区域；具体名称来自本项目导航分工。

当前问题：旧版有 main 与一个完整阅读目录。新版加入章目录与本章路线后，若仍用同名 nav，会让结构回查失去区别。

本轮决定（调整采用）：保留一个 main；整本目录标“全部章节”，当前章路线标“本章路线”，章节继续阅读保留自己的导航名；弹层目录也明确命名，不重复 main。

完成条件：DOM 中 main 仅一个；全部章节、本章路线、章节继续阅读三类导航有不同名称；此处不宣称真实读屏使用已通过。

[完整方法卡](../methods/A076.md)。

## A077 · 每个阅读与实验操作均可键盘完成

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)。观察：功能应可通过键盘完成且不要求特定敲击时序；原生链接、按钮和表单能降低自定义按键负担。

当前问题：旧版多数控件为原生 HTML，是可保留的基础；本轮新增阅读设置和导航也必须一起验收。

本轮决定（采纳）：保留 button/select/input/details；链接用于前往位置，按钮用于动作；不用仅 hover 可见的必要操作。

完成条件：只用 Tab、Shift+Tab、Enter、Space 和原生选择键，完成章节导航、全文切换、四个实验与答案展开。

[完整方法卡](../methods/A077.md)。

## A078 · 局部滚动区可以进入，也可以离开

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html)。观察：键盘进入组件后应能用键盘离开；若退出方式超出通常约定，应告知用户。

当前问题：旧版横滚表格已有 tabindex=0，但新增目录、搜索或浮层可能制造焦点困住的情况。

本轮决定（采纳）：表格横滚区使用自然 Tab 顺序，方向键可滚；非模态目录不要人为循环拦截焦点。

完成条件：对目录、宽表、代码区与四个实验逐一 Tab 进入并离开，Shift+Tab 可反向离开，无死循环。

[完整方法卡](../methods/A078.md)。

## A079 · 切章后焦点随阅读目标移动

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)。观察：当导航顺序影响理解或操作时，焦点顺序应保留意义；DOM 与动态焦点安排共同决定顺序。

当前问题：旧 showChapter 只滚动目标，不转移焦点；窄屏目录关闭后点中的链接可能处于隐藏内容内。

本轮决定（调整采用）：用户明确点击章节或上下章时，把焦点移到该章标题；仅切换字号、主题或全文模式时保留操作焦点。

完成条件：从目录和上下章操作切章后，document.activeElement 是可见目标标题；后续 Tab 顺着本章；不使用正 tabindex。

[完整方法卡](../methods/A079.md)。

## A080 · 所有控件显示稳定的焦点环

来源：[原页](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。观察：可键盘操作的界面应有可见焦点指示；指示不能在获得焦点一段时间后自行消失。

当前问题：旧版已有 focus-visible，但选择器未覆盖 input/select；深浅色卡片上焦点色需重新测算。

本轮决定（调整采用）：使用 :focus-visible 统一覆盖按钮、链接、输入、选择框、summary 与程序目标；采用清楚且持续的外环。

完成条件：Tab 遍历每类控件，焦点位置始终可辨；无 outline:none 而无替代样式；浅深背景逐一核查。

[完整方法卡](../methods/A080.md)。
