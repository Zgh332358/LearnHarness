# 100 轮研究记录独立核验

核验日期：2026 年 10 月 7 日。对象为 `loops/registry.json`、十份分段记录、`references/evidence/observations.json`、案例证据文档及 `browser-checks.json`。本核验不改教程或当前大纲，不涉及真人学习效果验证，未读取 learnDSH／DSH 仓库。

## 结论与适用边界

**现有材料能够证明已形成 100 条编号连续、可追溯的研究／设计判断记录；尚不足以把它们全部认定为 100 个独立的读者学习问题。** 字符串唯一与链指针一致不等于问题独立。大部分条目提出了不同的教学约束，但 050／064、079／098 的新增差异较弱，088／099／100 等属于阶段管理和总结，需与具体教材学习问题区分。

未发现将未操作页面直接伪报为操作成功的明显声明。唯一成功操作记录为 Red Blob 的一次单步，另有三项加载受阻记录；页面文字观察始终与真实操作、真人验证分开。不过，本次不能仅凭文字记录与截图独立重建点击因果或证明全过程确实顺序发生。

建议保留原 100 条作为研究审计记录，对下文弱项逐条补正；在完成之前，对外用“100 条有依据的候选设计判断”而非“100 次独立验证成功”。不要把拟议补强直接写成已经完成的新研究。

## 结构与追溯检查

| 检查 | 实际结果 | 能证明什么 |
| --- | --- | --- |
| 记录数量与编号 | 100 条；编号严格为 1—100 | 记录数量和排序完整 |
| 问题、分析、设计变化 | 各有 100 个不同字符串 | 无逐字复制；不证明语义独立 |

| 引用 | 202 次引用，覆盖 100 个不同观察，涉及 16 个案例 | 引用覆盖范围 |
| 观察目录 | 127 个不同 ID；全部标为 `text` | 目录没有重复 ID；观察来源是页面文字 |
| 引用与观察内容 | ID、URL、观察文字全部对应，未发现悬空引用或内容不一致 | 内部引用有效 |
| 实际浏览器记录 | 1 项成功；R03、R14、R12 三项受阻 | 没有将全部 16 例都算成成功操作 |

“127 条观察”是整个目录的数量，循环实际引用其中 100 条，另外 27 条未使用。098 不应让读者误解为 127 条都已进入循环比较。

`work/record_loops.py` 会自动将上一条 `change` 复制为下一条 `previous_state`，再将研究证据附入记录。因此，前后指针检查只能验证录入格式。它不能单独证明每一轮都实际重新研究、根据上一轮发现修订了候选方案，或产生了新的判断。现有记录缺少各轮候选方案前后内容、实际审阅时间和逐项变更痕迹；不可从这一缺口直接断言伪造，也不可据自动连接宣称因果连续性已得到证明。

## 可供补强的新问题

下面只是后续研究候选，不是已经完成的轮次。采用时须新增具体比较、证据、取舍与变化，原记录保留到审计附录。

1. **聚餐预算与 Agent 运行预算同用“预算”时，怎样避免读者混淆？** 可从尚未使用的 R01-O07“步数与距离分开”研究两种量的并列呈现；技术含义由 Harness 官方资料补充。新产物应是业务费用与运行资源两张明确不同的字段说明。
2. **显示上下文容量时，字数、记录条数与 token 怎样区分？** 可研究 R03-O04“定义与可观察量相邻”，比较准确计量与示意占用；不能把若干条记录伪称真实 token 容量。
3. **写入任务记录是否等于更新模型权重？** 可从 R13-O03 的读写对照迁移同一记录的保存、取回、进入输入；技术解释另据官方资料，禁止把可微记忆机制直接套到 Harness。
4. **多个工具返回顺序不同，怎样让读者对应请求与结果？** 可研究 R11-O04 的指向关系与 R15-O03 的稳定编号，再用官方工具调用资料确认对应规则。该问题与 029 的单请求编号不同，需要明确展示到达顺序改变但配对关系不变。
5. **教学数据集与真实产品评测任务集怎样区别？** 可研究 R14-O03／O06 的数据条件与训练／测试指标区分，再结合官方 Agent 评测资料说明一段固定演示不能证明整体可靠性。

## 原站证据与操作声明核验边界

本次读取了观察目录、16 案例中的相关条目和保存的 R09、R11、R12 原页 HTML 片段。R09 的向量代数／几何、Remark／Note，R11 的 Demo／栈堆／已打印内容／永久链接／DOM 限制，R12 的 Possible mistakes／Event object／Tasks／滚动与尺寸边界，可在保存的正文中找到对应内容。未发现这些抽查观察与保存页面明显冲突。

没有重新联网打开全部 16 站，也没有把 127 条文字观察逐句重新核实为当前站点实况。内部引用有效不等于所有网页事实已再次独立确认。部分记录只带整页 URL 与短观察，具体定位保存在案例文档中；建议最终索引保留定位与适用限制，方便后续检查。

浏览器记录明确说 Red Blob 一次点击使对应 range 由 0 到 1。已查看 `work/redblob-step.png`，能看到访问编号及前进一步按钮；`work/redblob-before.png` 显示的是页面另一张起终点地图，不是同一控件的 0 状态。因此这对截图不能独立证明 0→1，原操作文字与运行日志才是该变化的依据。若需要可外部独立核验的操作证据，应补保存同一控件的前后状态或原始 DOM 值，保留时间与操作对象。

本报告不把截图不足判定为操作伪造。也没有发现研究记录宣称做过真人测试、操作全部案例、生成 Python Tutor 永久链接或成功运行 javascript.info 实验。

### 修订版结构结果

- 仍为编号 1—100 的 100 条记录，问题字符串仍全部不同。
- 前后连接全部一致；证据 ID、URL、观察文字均对应目录。
- 修订版含 200 次引用，覆盖 103 个不同观察；观察目录仍为 127 条。初版的 202 次／100 个数字只适用于候选快照，不能混用。
- 069／070／073 已明确标为本项目设计约束，原站没有实测相应行为；不再把教材启发当成原站功能验证。
- 029／053／084 已注明教材只支持展现方法，技术规则另据指南官方资料。分工得到修正；若要求单条记录可完全独立查证，仍可把“指南相关章节”进一步写成具体技术 URL 或来源编号。

修订后的六项关键弱点已得到实质补强。现有材料可以作为 100 条有来源的研究／设计判断供规划使用。093／094／097 等仍属于来源组织和证据管理约束，因此“100 条研究决策”与“100 个直接面向读者的学习问题”应继续区别；本复核不根据问题字符串唯一性替作者证明后一个更强的计数口径。

本次追加只核验新记录的内容和追溯，没有重新联网研究上述来源，也没有操作新实验。根执行者的重新对照声明、保存的教材观察与设计变化共同构成修订记录；它们不构成真人学习效果或原站交互成功的新增证明。
