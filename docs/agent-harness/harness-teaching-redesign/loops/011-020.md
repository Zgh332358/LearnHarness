# 第 011—020 轮研究判断

证据为原作者页面文字。设计约束与Harness技术规则分别说明；6条经独立复核补作具体对照，初版与修订日志保留。

## 011 · 互动示例是否要随机生成？

上一轮：所有交互配静态示例和关系说明；图不承担唯一解释，模拟省略项就近注明

证据：[R14-O04](https://playground.tensorflow.org/)：数据区有 Regenerate 按钮。；[R08-O05](https://ncase.me/polygons/)：要求同一模拟多跑几次。

对照与判断：随机起点会使前后差异难归因。演示机制时需要固定事实，统计可靠性才需要重复样本。

决定：固定教学样例。新增约束：默认数据固定，重复演示结果可解释；不把100轮研究或模拟计为真实可靠性实验

## 012 · 控制条件该选连续滑杆还是离散选项？

上一轮：默认数据固定，重复演示结果可解释；不把100轮研究或模拟计为真实可靠性实验

证据：[R03-O03](https://seeing-theory.brown.edu/basic-probability/index.html)：【观察：页面文本】硬币说明可拖动右侧蓝色概率条，改变硬币权重。；[R16-O02](https://pudding.cool/2019/04/text-prediction/)：作者让读者选择账号和文本，用滑杆改变文本位置。

对照与判断：概率或时间本身连续才适合滑杆；授权、超时、状态未知是明确分支，滑杆反而伪造连续关系。

决定：按数据类型选择。新增约束：阶段用步骤按钮；权限、结果状态用离散选项；不设虚构能力分数滑杆

## 013 · 前后变化应该显示哪些不变项？

上一轮：阶段用步骤按钮；权限、结果状态用离散选项；不设虚构能力分数滑杆

证据：[R10-O05](https://immersivemath.com/ila/ch02_vectors/ch02.html)：图 2.3 的不同状态图注强调向量位置改变后，方向和长度不变。；[R16-O05](https://pudding.cool/2019/04/text-prediction/)：第二块给同一文本并列展示四个来源模型的候选。

对照与判断：如果任务、模型与工具同时变化，读者不能定位原因。教材要明确保持相同任务只改一项条件。

决定：采用受控对照。新增约束：对照框列固定目标和被改变条件，反馈指出只因此改变的检查或后续动作

## 014 · 新概念应该一次增加多少？

上一轮：对照框列固定目标和被改变条件，反馈指出只因此改变的检查或后续动作

证据：[R06-O01](https://ncase.me/crowds/)：目录依次增加传播规则。；[R13-O05](https://distill.pub/2016/augmented-rnns/)：翻译示例对照单个摘要向量与逐词保留的信息。

对照与判断：完全主线必须完整，但初次演示可先一轮查询，再增加反馈和停止分支，而不是一次展开所有异常。

决定：渐进呈现。新增约束：主例按最小轮次→多轮→异常扩展，扩展仍沿同一对象和术语

## 015 · 如何避免同一对象每章改名？

上一轮：主例按最小轮次→多轮→异常扩展，扩展仍沿同一对象和术语

证据：[R03-O01](https://seeing-theory.brown.edu/basic-probability/index.html)：【观察：页面文本】本章用硬币、骰子、卡牌分别解释三种统计概念。；[R16-O08](https://pudding.cool/2019/04/text-prediction/)：后续 Friend Data 块重复账号、模型与文本选择控件。

对照与判断：稳定阅读方式减少重新学界面的负担。输入、模型输出、检查、执行、返回、记录在章节间应一致。

决定：建立统一视觉语法。新增约束：同一职责使用相同名称与标记；不同机制不能只换标题而复用错误流程

下一轮：颜色是否足够说明状态？

## 016 · 颜色是否足够说明状态？

上一轮：同一职责使用相同名称与标记；不同机制不能只换标题而复用错误流程

证据：[R14-O07](https://playground.tensorflow.org/)：正文分别说明数据点、连线和背景颜色所表示的量。；[R15-O07](https://learngitbranching.js.org/generatedDocs/levels.html)：合并关卡解释分支颜色及提交颜色混合所代表的关系。

对照与判断：多处颜色有不同意义容易误解，色觉与打印也会丢失编码。Harness更需要明确的状态文字。

决定：文字为主颜色辅助。新增约束：每状态写明未执行／已返回／未知／待批准，图例统一；不使用混色表达复杂关系

下一轮：关系箭头是否可以只画方向？

## 017 · 关系箭头是否可以只画方向？

上一轮：每状态写明未执行／已返回／未知／待批准，图例统一；不使用混色表达复杂关系

证据：[R07-O03](https://ncase.me/loopy/)：建模入口用圆和箭头描述。；[R15-O03](https://learngitbranching.js.org/generatedDocs/levels.html)：第一关用 C0、C1 标识提交，解释箭头表示祖先关系。

对照与判断：因果影响、数据发送、控制调用、授权检查是不同关系。没有说明的箭头只制造似懂非懂。

决定：标动作与对象。新增约束：箭头附近标发送本轮输入、提出请求、调用工具、返回结果或更新记录；权限用检查框

## 018 · 通用职责图能否代表每个产品部署？

上一轮：箭头附近标发送本轮输入、提出请求、调用工具、返回结果或更新记录；权限用检查框

证据：[R13-O08](https://distill.pub/2016/augmented-rnns/)：图注区分据论文改写的图与直接引用的图。；[R07-O07](https://ncase.me/loopy/)：开头主动缩小工具作用承诺。

对照与判断：不同实现可能把职责放客户端、服务端或SDK内。教学图需表明是职责模型，而非某产品部署实况。

决定：限制概括范围。新增约束：图注明逻辑职责与部署位置可以不同；具体产品位置另据官方资料解释

下一轮：术语解释应该放在哪里？

## 019 · 术语解释应该放在哪里？

上一轮：图注明逻辑职责与部署位置可以不同；具体产品位置另据官方资料解释

证据：[R10-O07](https://immersivemath.com/ila/ch02_vectors/ch02.html)：定义长度后，正文把 scalar 解释为普通数字，并把具体长度计算延后。；[R12-O01](https://javascript.info/introduction-browser-events)：正文先把 event 解释为发生事情的信号，再列点击、按键、提交等具体事件。

对照与判断：让非技术读者来回查术语表会打断理解。首次出现时先说它具体负责什么，再给常用英文。

决定：就近最低解释。新增约束：上下文、状态、工具请求等首次出现以作用+具体数据举例，附录负责回查

## 020 · 研究教材的维护状态是否决定可用方法？

上一轮：上下文、状态、工具请求等首次出现以作用+具体数据举例，附录负责回查

证据：[R03-O08](https://seeing-theory.brown.edu/basic-probability/index.html)：【观察：页面文本】章末提供下载与下一章入口，页面也列章节导航。；[R02-O07](https://worrydream.com/ExplorableExplanations/)：【观察：页面文本】资料核查例给出指词、按 W、输入查询词的操作。

对照与判断：旧页面的交互可能不能运行，但明确的教学结构仍可分析；不能据旧网页承诺当下功能可用。

决定：方法与现状分开。新增约束：记录教材归档和加载限制；只迁移已读明的教学原则，控件可用性须单独核查
