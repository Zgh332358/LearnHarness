# D04｜就近图文解释与同事件多表示

方法类型：展现（display）。综合日期：2026 年 10 月 7 日。

本文根据 16 个案例的研究记录提炼展现规格，不是现有教程大纲审阅或 HTML 实现。来源部分是已有页面观察；下面的迁移方案、排版与检查均为基于需求基线的设计推断，尚未经过目标读者实验。部分源观察属于交互，但本文只提炼它们需要怎样显示对象、数据与解释。

## 目标问题

读者读完一段后，要滚动多远才能看见它说的对象？图、术语、原始数据是否指向同一件事，还是各自建立一套概念？

## 排版与图的具体结构

1. 一个局部教学单元只处理一个问题，按“具体对象与问题→关系图或数据→解释该变化的文字”排列。图紧接所解释的规则，图注用对象名称、事件编号或字段名指认内容。

2. 同一事件可以同时有流程位置、数据单和一句业务含义，三者共享编号；不必照搬某案例的全部表示。每个视图应补充一种必要信息。

3. 术语首次出现时给最低够用的解释，并指向当前对象。例如字段说明写在字段旁，不要求读者跳到独立术语墙再记住含义。

4. 当前步骤的解释放在图或数据单旁，直接陈述输入、变化和后果。不要让正文引用模糊的“上图”“这里”“它”。

5. 来源、核查日期和“教学归纳／真实记录”标记附在相关事实或图注上。理论和实际不一致时，保留差别，不能用排版让它们看起来相同。

## Harness 中适用与不适用的地方

**适用：** 适合逐项解释工具返回、参数结构、上下文选择与压缩、动作请求和工具实现的关系，以及当前产品责任表中的来源。对非技术读者保留真实字段，但可按业务含义配一句解释。

**不适用：** 不适合把邻近解释当成学习效果已验证；原案例的六种表示或代码容器不能全量照搬。参数表不应取代任务主线，模型内部数学图也不能冒充 Harness 机制。

## 手机与静态回退

**手机：** 图、数据单与对应解释作为一个纵向单元一起出现；图注不能与图分离到下一大段。优先使用可换行的字段，长代码不是理解机制的必经内容。

**静态回退：** 每个图都具有独立图注：对象、关系、当前状态与结论；每条数据含字段解释。无法显示图时，文本仍能说明同一事件。来源保留可打印链接文字或注号。

## 使用本方法时的检查

- 去掉图像后，文字仍说明实际传递和变化。
- 图、表、正文中的对象和编号一致。
- 每种并列表示都有必要作用，删掉冗余视图不会断开解释。

这些检查是未来教材与实现的验收要求，不是已经通过的测试。
