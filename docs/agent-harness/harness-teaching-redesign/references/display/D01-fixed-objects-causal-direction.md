# D01｜固定对象分区与因果方向

方法类型：展现（display）。综合日期：2026 年 10 月 7 日。

本文根据 16 个案例的研究记录提炼展现规格，不是现有教程大纲审阅或 HTML 实现。来源部分是已有页面观察；下面的迁移方案、排版与检查均为基于需求基线的设计推断，尚未经过目标读者实验。部分源观察属于交互，但本文只提炼它们需要怎样显示对象、数据与解释。

## 目标问题

读者能否指出谁取得什么资料、谁提出动作、谁真正执行，以及反馈送往哪一轮？对象在图中不断换位置或箭头没有类型，会让人把职责和时间顺序混为一谈。

## 排版与图的具体结构

1. 先确定需要追踪的对象，再放关系线。建议固定“本轮输入”“模型输出”“条件检查与执行”“工具返回”四处；外部记录放在独立区域，目标与要求作为可回查参照。这里是图的排版职责，不是组件部署图。

2. 主方向沿阅读方向排列；每条线用短标签说明传递的是输入、动作请求、结果还是记录读取。若需要表示控制判断，用不同线型及条件文字，与数据传递区别。

3. 模型输出后的分支保持可见：请求执行、直接答复、等待或结束均有位置。不能让工具框成为模型输出的必经路线。

4. 同一学习例中的对象位置与名称保持不变，只突出当前发生的传递。未参与的对象可减弱，但标签仍在。返回线明确指向“下一轮输入”，不要形成让人误以为同时存在的圆形循环。

5. 每个对象旁只给该例的具体数据或状态，完整协议字段按需查看。不要通过尺寸、景深或包围盒表示未定义的“高低层”。

## Harness 中适用与不适用的地方

**适用：** 适合展示一次调用、结果进入后续输入、外部记录被检索后再送入、直接答复与工具请求分支，以及本机／服务端职责分布。部署需要另画实际运行地点边界，不能从本图的左右位置推断。

**不适用：** 不适合把模型内部判断画成已观察到的逐步推理，也不适合把 Skill、MCP、SDK、运行环境全部放在同一条必经链。数据传递、权限和因果影响不能共用无说明的箭头。

## 手机与静态回退

**手机：** 窄屏将四个区按固定顺序纵向排列，反馈单独标注“进入第 N+1 轮”。用事件编号配对跨屏线的起终点，避免需要缩放查看整张巨图。

**静态回退：** 提供同编号的列表：发送方→内容→接收方→状态变化；保留直接答复分支与外部记录读取。取消高亮后，各对象和关系仍可读。

## 使用本方法时的检查

- 固定一个结果编号，能沿图找到接收它的下一轮输入。
- 拿掉颜色和动画，传递类型仍有文字或线型可辨。
- 图旁说明逻辑职责；部署位置另有明确边界。

这些检查是未来教材与实现的验收要求，不是已经通过的测试。
