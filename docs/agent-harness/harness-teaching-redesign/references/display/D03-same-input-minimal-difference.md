# D03｜同一输入的最小差异对照

方法类型：展现（display）。综合日期：2026 年 10 月 7 日。

本文根据 16 个案例的研究记录提炼展现规格，不是现有教程大纲审阅或 HTML 实现。来源部分是已有页面观察；下面的迁移方案、排版与检查均为基于需求基线的设计推断，尚未经过目标读者实验。部分源观察属于交互，但本文只提炼它们需要怎样显示对象、数据与解释。

## 目标问题

两幅图不同，到底是规则、任务、模型、数据还是起点不同造成？读者要看到某一条件的具体作用，需要知道哪些条件保持不变。

## 排版与图的具体结构

1. 对照上方列出共同输入、共同任务和共同起点，并单列唯一改变项。教学规则演示优先复用同一份记录，而不重新抽样后声称只改了一项。

2. 宽屏使用左右两个紧邻面板；两侧的字段顺序、事件编号与输出量一致。变化项用“原条件→新条件”文字标出，不能仅靠高亮让读者猜。

3. 对照下方给差异表：改变项、保持项、发生变化的事件或状态、未变化的部分。先解释为什么不同，再介绍相关技术名称。

4. 比较停止策略时，同时保留执行状态、业务满足与事实未知。比较指标时分列次数、费用、等待时间及验收，不汇成一个“好坏”颜色。

5. 正常例旁可以放一个反例或边界例，但每次只引入一个新限制。反例用于驳回绝对陈述，不用于推出总体成功率。

## Harness 中适用与不适用的地方

**适用：** 适合同一返回在不同预算／重试／停止规则下的分支、存储但未取回与已纳入输入、请求已提出与实际已执行、执行成功与业务仍未知。可用它解释新增机制修复了什么。

**不适用：** 不适合把两次不同的真实模型输出直接当成控制实验。模型版本、上下文、采样、环境和时间均可能影响结果；若使用真实样本，必须写明只能说明这些运行记录。并行工具动作的顺序也不天然可交换。

## 手机与静态回退

**手机：** 先显示共同条件，再纵向放两个同构面板，最后放一张差异表。可用选择按钮切换但需始终显示当前条件；静态阅读不能依赖来回切换记忆差别。

**静态回退：** 两面板或两行数据完整保留，差异表直接列出变化。对于不能并排的长数据，只截取与单一差异有关的字段，并列明省略范围。

## 使用本方法时的检查

- 读者能说出唯一改了什么以及哪些条件未改。
- 对照不以一次结果证明普遍优势。
- 反例与正常例使用同一组输出字段。

这些检查是未来教材与实现的验收要求，不是已经通过的测试。
