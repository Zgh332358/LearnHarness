## 证据取得方式与边界

本案例只通过联网工具读取原页面文本，没有操作页面控件、没有验证图形位置和响应。以下「观察」只陈述原文可证实的界面说明或编排；「迁移判断」属于针对 Harness 教学需求的推断。原文说能拖动、切换或播放，不等于本轮已经操作成功。

只研究教材方法；未读取 DSH／learnDSH，未审阅现有 Harness 教程大纲，未制作 HTML。需要根代理统一在既有浏览器空间完成「待操作核验」。

## R04-O01｜局部与全局的运动控制

方法类型：交互（interaction）。证据模式：页面文本（text）。

**观察：** 开头说明每图可暂停，也可全局暂停动画。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 文章开头的播放说明，网页提取行 6。

**对应学习问题：** 读者能否停住变化去查某个状态，而非被动画速度带走？

**迁移判断：** 【推断】循环图默认单步，若提供播放，必须可暂停并保留选中事件与输入输出。

**限制与不适用原因：** 未点暂停；提取文本同时含默认开与关两种文案，不能判断实际默认值。暂停不等于真实任务取消。

**待操作核验：** 确认默认运动状态、局部按钮与全局按钮的作用范围。

## R04-O02｜先动熟悉对象，再定义量

方法类型：交互（interaction）。证据模式：页面文本（text）。

**观察：** 风扇例提供速度滑杆，随后解释角速度与单位。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 旋转段，网页提取行 9–13。

**对应学习问题：** 技术名称能否在读者已看见的具体变化上落地？

**迁移判断：** 【推断】先显示一次真实请求与返回，问发生了什么，再引入工具调用和结果这些名称。

**限制与不适用原因：** 未移动滑杆；不能声称速率标示方式。熟悉场景帮助接近术语，不应取代实际协议字段。

**待操作核验：** 改速度，核验变化、数值与单位是否对应。

## R04-O03｜删去妨碍因果理解的外形

方法类型：展现（display）。证据模式：页面文本（text）。

**观察：** 圆盘段明确用简单盘形替代会遮蔽特征的风扇形状。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 圆盘段，网页提取行 16–17。

**对应学习问题：** 视觉细节是否挡住了需要追踪的关系？

**迁移判断：** 【推断】Harness 图保留请求、检查、执行和返回的连线及数据，去掉无职责含义的外壳与景深。

**限制与不适用原因：** 替换理由来自作者陈述；未做可读性实验。删除内容只针对表现细节，不能删掉失败与未知状态。

**待操作核验：** 对比两图可见标记，确认简化后究竟增加了哪些可追踪信息。

## R04-O04｜时间可来回查，运动留下轨迹

方法类型：交互（interaction）。证据模式：页面文本（text）。

**观察：** 圆盘例允许用滑杆前后控制时间，并留下路径与展开弧。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 圆盘轨迹说明，网页提取行 19–21。

**对应学习问题：** 读者能否从前后状态中追踪变化，而不靠记住动画？

**迁移判断：** 【推断】事件时间线可回看任一已记录状态，同时显示此前输入与此后记录的差异。

**限制与不适用原因：** 未拖时间轴；不能报告轨迹实现。回看界面不是撤销真实动作，真实执行不能随时间滑杆倒退。

**待操作核验：** 时间往返，观察历史轨迹与展开视图怎样更新。

## R04-O05｜用标记显示变化关系

方法类型：展现（display）。证据模式：页面文本（text）。

**观察：** 圆盘上的六点配速度箭头，解释半径与线速度的关系。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 圆盘速度说明，网页提取行 17、22–27。

**对应学习问题：** 箭头的含义是否具体，读者能否知道它编码哪个变化？

**迁移判断：** 【推断】流程箭头标注实际传递的请求编号或结果编号，不使用无名流光代表“智能在工作”。

**限制与不适用原因：** 仅证实作者解释了箭头的量；未检查大小与方向实现。Harness 数据连线通常表示传递，不应借用物理速度大小。

**待操作核验：** 核对箭头方向、长度、图例及文本关系，确认不是只作运动装饰。

## R04-O06｜同一控制同时显示收益与代价

方法类型：交互（interaction）。证据模式：页面文本（text）。

**观察：** 半径比例可调的例子同时解释输出速度与力的取舍。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 力矩与传动比较段，网页提取行 93–98。

**对应学习问题：** 改一个策略后，读者能否看见多项结果，而非只看到好的一面？

**迁移判断：** 【推断】同一重试上限变化同时显示等待时间、费用和重复副作用风险；规则值有依据，风险不造假数字。

**限制与不适用原因：** 未调比例；只是作者明示的控制及关系。实际费用和成功率的权衡应来自测量，不能像齿轮比一样确定。

**待操作核验：** 调比例，检查速度与力是否同时可读，固定输入是否说明。

## R04-O07｜直接操作有效成分

方法类型：交互（interaction）。证据模式：页面文本（text）。

**观察：** 力的角度可调，红色切向分量解释实际产生力矩的部分。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 力矩段，网页提取行 60–73。

**对应学习问题：** 输入内容中哪些部分实际参与了当前决策？

**迁移判断：** 【推断】展示完整外部记录与本轮实际送入的条目，选中条目解释它支持哪一条件，未送入内容保持可见但明确未参与。

**限制与不适用原因：** 未调角度；红灰编码来自文字。模型没有可公开证实的逐条决定因果，迁移只说明系统发送范围。

**待操作核验：** 改变角度，核验分量、方向及正负变化的可读性。

## R04-O08｜先交代假设失效，再引入改进机制

方法类型：展现（display）。证据模式：页面文本（text）。

**观察：** 摩擦盘的理想假设先被打滑打破，随后引入齿轮。 [原页面](https://ciechanow.ski/gears/)

**证据定位：** 齿轮段开头，网页提取行 101–105；结尾也说明真实条件更复杂。

**对应学习问题：** 新增机制是否对应可指出的失败，而非因为有新名词就加入？

**迁移判断：** 【推断】先展示任务中断后无法判断已发操作，再引入外部核对和恢复记录；每个机制给出要修复的具体问题。

**限制与不适用原因：** 本轮只读反例和引入顺序；未观察打滑图。恢复方案不能保证所有外部系统可核对，需保留不可恢复的边界。

**待操作核验：** 查看打滑例与随后齿轮例的切换，核对失效条件如何呈现。
