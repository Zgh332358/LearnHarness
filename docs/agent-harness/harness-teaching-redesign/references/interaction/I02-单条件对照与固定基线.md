# I02 单条件对照与固定基线

方法状态：候选综合，2026 年 10 月 7 日。来源是 text 观察；原网站交互与本教材效果均未操作验证。

## 目标问题

读者能否解释一个设置为何改变某个检查或后续动作，同时指出没有改变的输入？操作很多参数但不知道因果，不是本方法要达到的结果。

## 最小控件

一个有明确含义的选择框、数值输入或两个预设按钮，配“恢复本例基线”。默认只开放一个条件。对照区分别显示基线与变更后的状态，并就近列出固定条件。离散条件不强行使用连续滑块。

## 前 → 操作 → 后

| 前 | 操作 | 后与应显示的解释 |
| --- | --- | --- |
| 教学价格记录为人均 140 元，预算为 150 元；其他条件固定 | 将预算改为 130 元 | 预算检查从满足变成不满足；价格记录与来源保持不变 |
| 允许继续查询，已用次数与已知资料固定 | 将剩余调用上限改为 0 | 运行条件阻止继续；不代表业务已经完成或现有资料失效 |
| 已有一次结果未知的预订操作 | 修改重试规则 | 显示新规则如何处理已有未知状态；不默认清除先前动作 |
| 已比较变更 | 恢复本例基线 | 恢复教学条件及固定起点，明确不触及现实系统 |

150、130、140 均为示例值，用于解释检查关系，不是实际餐厅报价。对比程序的已知规则，可以得到确定分支；对比模型判断，须使用标明来源的运行记录或声明为虚构，不承诺同条件必然得到同输出。

## Harness 迁移条件

先说明变量属于业务条件、运行资源、工具返回或授权，不能把它们都称为“参数”。每个变化须关联实际字段、触发条件与下一步。修改输入与推进事件分开；已提交的请求须保留当时版本。涉及随机性或模型生成时，记录其他不受控因素，不拿一次演示估计成功率。

## 禁止的误导

不编造费用与可靠性的确定函数；不把“增加上下文”写成保证更聪明；不让重置初态混进单条件实验而未告知；不以固定教学路线代表所有产品行为；不把餐费预算和 AI 运行费用混成一个限制；不把 LOOPY 的因果影响箭头直接替代数据流或控制条件。

## 键盘与手机要求

选择项可用键盘操作；数值控件同时给出当前值、单位和可理解标签。手机可用预设按钮替代精细拖动，并按上下顺序展示两种条件。不能仅用颜色显示差异，变化字段有文字标记。提交后的状态更新须可感知且不自动跳离阅读位置。

## 证据边界与后续验证

来源仍为 text。实际要测的是只改一项时哪些字段变了、哪些没变，恢复后是否回到同一教学样例。按这些规则实现后仍需目标读者解释因果；控制界面工作正常不等于理解已得到证明。
