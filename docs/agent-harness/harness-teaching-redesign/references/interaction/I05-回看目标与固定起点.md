# I05 回看目标与固定起点

方法状态：候选综合，2026 年 10 月 7 日。来源是目标回查、重置与再生成的 text 观察；未操作这些控件。

## 目标问题

读者操作几个步骤以后，能否随时核对原始目标与当前约束？再次试验时能否回到同一教学条件，而不误以为真实动作或外部历史可以清空？

## 最小控件

常见位置的“查看目标”与“重置本例”按钮，当前条件版本提示。重置优先恢复固定样例，不用随机再生成代替可比较起点。查看目标与重置须分开，因为前者只改变展示，后者改变教学状态。

## 前 → 操作 → 后

| 前 | 操作 | 后与应显示的解释 |
| --- | --- | --- |
| 正在查看第三个事件 | 查看目标 | 就地显示人数、预算、忌口、日期、交付范围；当前事件不变 |
| 用户条件曾改变 | 查看目标 | 区分最初要求、当前版本及改动时点，不覆盖历史请求参数 |
| 完成一次虚构查询对照 | 重置本例 | 恢复相同起始数据与教学规则，方便只改一项再次比较 |
| 正在回看曾提交的预订记录 | 返回前一事件 | 只回看历史；不能把已提交事实变成未提交 |
| 需要中断后继续的教材例 | 进入恢复情境 | 读取既有记录，并检查现实状态是否需要核对；不从空白重新演示 |

“重置本例”“回看历史”“恢复任务”是三个不同动作。重置允许清除虚构演示进度；恢复需要保留已有事实与外部状态。任何与现实系统相连的操作，都不因教材界面返回起点而被撤销。

## Harness 迁移条件

目标包含具体内容而非一个“任务”标签；相对日期要在示例条件中明确。先定义哪些状态属于教学视图、哪些属于外部记录。现实任务恢复需要说明最后确认事件、待核对动作与过期资料，目标回查按钮不等同持久状态管理。

## 禁止的误导

不把 reset 写成取消订单；不把返回上一页写成恢复运行；不把目标始终可见写成模型每次一定看到；不偷偷随机换数据后称“同一条件再试”；不要求读者记住隐蔽口令才能回看目标。

## 键盘与手机要求

两个按钮有不同标签和语义，可由键盘及触屏独立使用。展开目标后能关闭并返回原控件；不遮住全部过程记录。窄屏可用折叠区保留关键条件摘要。重置会丢弃读者当前教学选择时，清楚说明影响并提供稳定返回路径，但不把教学点击变成层层审批。

## 证据边界与后续验证

来源为 text，未实测回查、重置或随机性。后续确认重置前后起点一致、目标版本保留、回看不写入外部状态，且手机与键盘能回到原步骤。未声称目标读者已能区分三类动作。
