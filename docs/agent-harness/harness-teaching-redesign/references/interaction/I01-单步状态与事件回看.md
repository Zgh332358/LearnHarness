# I01 单步状态与事件回看

方法状态：候选综合，2026 年 10 月 7 日。证据来自已保存的页面文字观察；未操作原网站，未实现 Harness 交互。此处的键盘与手机条目是本教材的待验证要求。

## 目标问题

读者能否停在一个事件上，指出谁提出请求、谁执行、什么已经返回、哪些资料尚未产生，以及下一轮为什么可以开始？连续播放容易把这些分界压成“AI 在办事”，单步的意义是让它们可被分别检查。

## 最小控件

“下一事件”“上一事件”两个按钮，当前事件编号与总数。默认暂停。先不增加速度、播放模式或时间滑块；可选连续播放必须能暂停，且不替代逐步阅读。条件修改使用另一控件，不让“下一事件”同时改输入。

## 前 → 操作 → 后

| 前 | 操作 | 后与应显示的解释 |
| --- | --- | --- |
| 模型输出 request_01，拟查询甲餐厅；没有 result_01 | 下一事件 | 程序检查参数与运行条件；显示执行是否获准及理由 |
| 检查通过，尚未调用工具 | 下一事件 | 工具接收请求，状态改为执行中；请求发起者与执行者分别标注 |
| 执行中 | 下一事件 | 显示 result_01 或错误；对应 request_01，保留未知字段 |
| 结果已返回但未整理 | 下一事件 | 外部记录更新；显示哪些材料将进入下一轮输入 |
| 后续事件已显示 | 上一事件 | 回看旧记录与当时可见资料；外部系统与已执行动作保持原状 |

每步标出“新增、改变、不变”三类对象。本轮未产生的结果不能提前出现；回看是阅读记录，不是倒转执行。

## Harness 迁移条件

用记录或明确的教学规则定义事件；模型输出、工具调用和程序检查不能合并成一个节点。沿同一表示方式显示请求、结果和状态。停止事件可以是交付、等待、取消或达到上限，必须有具体理由。记录可支持读者追踪，却不代表公开模型内部思考。

## 禁止的误导

不把点击按钮写成真的调用了模型；不把模型请求写成工具已经执行；不把回退写成撤销真实订单；不把所有节点都画成模型决定。默认文字也须给出完整的一轮过程，不能要求操作后才知道关键分界。

## 键盘与手机要求

按钮可用 Tab 到达、Enter 或 Space 激活；焦点保留在控件上。状态变化需有简短文字播报，不能只靠动画或颜色。手机上输入、事件和状态可顺序堆叠，编号保持一致，不要求横向拖动大图。关闭动画时仍能阅读每步记录。
