# I03 先作预测，再看依据反馈

方法状态：候选综合，2026 年 10 月 7 日。引用的是页面文字、题目或教师建议；未验证原站的预测控件、自动评分或分支效果。

## 目标问题

读者能否在解释出现前作出判断，然后用请求、结果或规则修正判断？本方法针对可检查的分界，例如“查询执行成功”与“已证实有包间”是否等价。

## 最小控件

二至三个清楚的选项，“查看依据”按钮，以及允许修改选择的入口。可以不设分数。选择后的解释要对应本次选择，不能所有答案都只显示“继续加油”。关键正文不因尚未作答而不可读。

## 前 → 操作 → 后

| 前 | 操作 | 后与应显示的解释 |
| --- | --- | --- |
| 展示一次查询请求与教材返回规则，返回内容尚未展开 | 预测下一轮会获得哪类材料 | 保存选择；不立即替读者改成正确答案 |
| 展示工具成功返回，但可订字段为未知 | 选择“已确认”“明确不可订”或“仍未知” | 查看依据后定位未知字段，解释成功返回不提供可订结论 |
| 上轮失败已记录，允许另一来源查询 | 预测下一轮要看到哪些材料 | 对照实际组装的输入：要求、错误记录、可用工具及进度 |
| 判断与依据不一致 | 修改选择 | 保留新的判断，并明确哪条依据促成修正；不要求重新浏览全部内容 |

第一行的预测基于显式教学规则，不是假装知道现实服务将返回什么。涉及开放生成时，应预测输入、状态或权限这类可核对关系，避免把模型自由表达设成唯一标准答案。

## Harness 迁移条件

选项分别对应一种真实误解，反馈必须引用当前显示的字段、条件或事件编号。把“看到答案”与“执行动作”分开；先预测不应影响现实权限或触发外部写入。反馈应回答为什么此选项成立，以及它不能说明什么。

## 禁止的误导

不把答案唯一性扩展到开放业务判断；不编造模型内部思考作解答；不让“工具成功”成为所有问题的标准答案；不以题目完成百分比证明已经掌握 Harness。Python Tutor 的教师建议也不能被描述为原网站已经实现的自动预测题。

## 键盘与手机要求

选项以语义明确的单选组呈现，键盘可移动与选择；反馈与选项处在同一阅读区域。手机不用悬停揭答案，也不要求同时看四列。查看依据后保留选择，播报结论及关键原因，别让自动滚动造成选择与反馈脱节。

## 证据边界与后续验证

所有来源 observed_mode 为 text。后续验证每个选项是否有准确反馈、选择改动是否保留正确状态，以及无交互时默认解释是否完整。随后才能做目标读者对照，不声称预测活动已被本项目证明有效。
