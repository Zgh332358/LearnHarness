# I06 局部详情与证据反查

方法状态：候选综合，2026 年 10 月 7 日。来源是按需入口、局部核查与结果依据的 text 观察；未确认原站弹层、展开或悬停是否工作。

## 目标问题

主线保持清楚时，读者能否检查一个具体请求的参数、一个结果的未知字段或一项事实的来源，并回到原来的论证位置？详情应回答当前问题，不能成为另一份孤立术语表。

## 最小控件

对象旁的“查看参数”“查看返回”或“查看来源”入口，能够就地展开与收起。只保留与当前对象有关的一个详情层。最终结论可通过记录 ID 反查对应事件，不要求读者先学搜索语法。

## 前 → 操作 → 后

| 前 | 操作 | 后与应显示的解释 |
| --- | --- | --- |
| 主线显示 request_01 拟查包间 | 查看参数 | 展示餐厅标识、日期、人数、字段含义及条件版本 |
| 主线显示查询有响应，可订仍未知 | 查看返回 | 展示真实或明确虚构的结构化字段，定位未知值 |
| 比较表称价格符合预算 | 查看来源 | 展示 result ID、来源、取得时间和适用范围；不跳失主线 |
| 读者已看详细字段 | 收起详情 | 保留关键结论与当前阅读位置，已展开对象仍可再次核对 |
| 协议字段暂时不影响当前判断 | 展开协议说明 | 与最小业务含义分层呈现；核心职责解释不藏在详情里 |

## Harness 迁移条件

详情与可观察对象配对：工具说明说可做什么，请求说拟做什么，实现负责执行，结果说实际返回什么。来源可核查不等于事实必定新鲜或正确。先给字段业务含义，再按需给协议细节；原始技术数据仍可找到。

## 禁止的误导

不让悬停成为唯一入口；不把过程记录写成模型内部思维；不把资料链接当外部动作成功凭证；不把所有正文折叠起来让读者必须逐个开卡片；不把工具说明与实际实现混在同一段标签中。

## 键盘与手机要求

入口可聚焦、可激活，展开状态有可感知标签。优先就地展开；若用弹层，关闭后焦点回到原入口，内容不被键盘困住。手机点击可打开详情，不依赖鼠标指向；长字段允许换行，技术原文保留易读替代表示。更新不把读者自动送到页顶。

## 证据边界与后续验证

来源仍为 text。后续检查每个 ID 的反查是否对应正确记录、展开是否保留位置、手机是否能够关闭详情，以及禁用动画或脚本时是否仍能读取核心内容与来源。此方法未证明学习效果。
