# 研究计划与 100 轮循环规则

## 执行顺序

1. 写入需求与验收基线。
2. 查询原作者或教材发布方的公开 HTML 教材；把展现与交互观察拆成方法证据。
3. 完成 100 轮有记录的研究对照决策。方法材料和证据可以并行搜集，编号决策由主执行者顺序审阅记录。
4. 第 100 轮结束以后，列出当前教程大纲与逻辑链，分别做技术、产品视角审阅。
5. 定稿新的大纲及图文交互规划。
6. 实施教程和 HTML，完成浏览器走查、公开发布检查、仓库同步与验收报告。

## 一轮究竟记录什么

每轮编号唯一，写明：上一轮状态、本轮学习问题、参考教材证据、证据方式（原页面文本/实际操作）、对照基线、保留/适配/拒绝的决定、具体变化或新增约束、下一轮问题。方法与证据文档可复用；每轮必须处理不同的可判断问题，不能重复描述同一观察来增加轮数。

100 轮是研究与教材设计对照的小循环，不声称有 100 位用户测试，也不声称进行 100 次实际浏览器实验。操作过的页面会另外记录步骤、观察结果和截图。未经操作的效果标为待验证，不把供应者文案当作交互已经可用。

## 循环推进

- 001—020：选择与核查教材，从目标读者任务确认哪些方法值得研究。
- 021—040：正文、图、例子、协议细节的排版与信息组织。
- 041—060：选择、步进、参数、状态、反馈、重置等交互因果。
- 061—080：学习序列、解释深度、错误反馈、可访问性与阅读连续性。
- 081—100：迁移方案、方法组合、复杂度控制与研究结论复查。

这些是关注重点，并不将真实发现强行归进某个编号范围。必要时调整问题，保持总计 100 次实际研究对照记录。

## 文件组织

- `references/evidence/`：原教材案例与可追溯证据。
- `references/display/`：按展现方法整理的对照文档。
- `references/interaction/`：按交互方法整理的对照文档。
- `loops/`：100 轮顺序记录，含引用与决策。
- `review/`：研究结束后生成的当前大纲、逻辑审阅与定稿。
- `validation/`：实施后的交互走查、窄屏、键盘及内容验证。

不复制原教材正文或资产来改名作为本项目内容。迁移的是学习机制与布局原则，Harness 例子、图和交互模型重新编写。
